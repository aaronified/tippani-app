# ADR-0033: The broken link is one mark and one toast, not a note on every screen

- **Status:** Accepted and built. The owner, looking at a banner on the Anthologies screen ("Showing what this phone last saw (2026-11-22). The server cannot be reached."), asked: *"Why is anthology the only screen with this 'cannot connect' infobox? It should be just a link broken icon somewhere with a toast once per app awake."* Replaces the per-screen note of [ADR-0022](ADR-0022-Everything-Reads-Offline-And-Changes-Wait-For-The-Server.md), [ADR-0030](ADR-0030-Anthologies-Draw-From-The-Phone-First-And-Ask-The-Server-Behind-It.md) and [ADR-0032](ADR-0032-Every-Server-Screen-Draws-The-Phones-Copy-First.md).

**Why.** Whether the server can be reached is a fact about the connection, not about a screen. The note was mounted by hand on thirteen screens, so it was one line of layout above each list, it was missing wherever nobody had mounted it, and it said the same thing a dozen times as the reader moved about. The state it reports is global: `OfflineCache.servedFrom` (the date of the copy on screen, or null) and `OfflineCache.refusal` (the server's words when it answered a refresh with a refusal). Those two notifiers stay the source of truth; only the drawing changes.

**Decided.**

| What | Where | Says |
|---|---|---|
| **The mark** (`ServerLinkIcon`, the Tabler `unlink` glyph in the error colour, read aloud as "Server not reachable", or "Server refused the refresh" once the server has answered and turned the refresh down) | In `ShellAppBar`, so every screen opened over the tabs wears it as the first action; and on the Server tab's glyph in the bottom bar (`ServerLinkBadge`), so every tab screen shows it | Nothing is drawn while the server answers. While the phone is showing a copy, the mark is there. Pressing it (in the app bar) shows a snack bar with the old note's words: the date of the copy and whether the server could not be reached or turned the refresh down, with its own reason when it gave one |
| **The toast** (`ServerLinkToast`, above the navigator, through the app's own `ScaffoldMessenger` key) | Once for each time the app is awake | The same words, the first time the link is found broken since the app came to the front |

**Once per awake.** The toast keeps a flag. It is set when the toast is shown and is not cleared by anything the link does: not by the server answering, not by a second screen falling back, not by the same server failing again. It is cleared by the app returning to the foreground after having been paused (`WidgetsBindingObserver`), and the toast is then shown again at once if the link is still broken. A cold start is a fresh flag. Nothing is scheduled: the toast listens to the notifier and to the lifecycle, so the app wakes on no clock.

**The mark is on the Server tab and in every `ShellAppBar`.** The tab screens draw their own headings rather than a bar, so the Server tab, the tab that stands for the server, carries it; every other bar is a `ShellAppBar` and carries it as its first action: a screen opened over the tabs, and the library's own bars, the selection bar included (checked at 360 dp with the leading button and five actions: no overflow). A screen that draws its own bar for some other reason calls the same widget.

**The mark is named for what happened.** While the server could not be reached the tooltip and the screen-reader label say "Server not reachable"; after a refusal (`OfflineCache.refusal` is set) they say "Server refused the refresh", because the server answered.

**The toast speaks the reader's language.** `ServerLinkToast` sits inside the language scope, and takes its words from its own context, not the `ScaffoldMessenger`'s, which is above the scope and would say them in English. It queues behind a message already on screen (an Undo, say) and never dismisses it; the mark's press does the same.

**One state for the whole connection, not one per screen.** `servedFrom` is shared. A successful read on any screen clears the mark, even when a screen further back is still showing an old copy. This is kept on purpose: the mark reports the connection, and a read that succeeded is proof the link is up, which is true whichever screen made it. The alternative, clearing only when the most recent read of the screen on top succeeded, would make the mark a claim about a screen again and need every screen to report to a registry; a stale screen further back refreshes itself the next time it is opened, and shows its own copy honestly until then.

**Rejected.** A banner on every screen (what it replaced: it costs a row of height on each, and every new screen has to remember to mount it); one banner in the shell above the tabs (it would push every screen down while the server is down, which is the screen state the reader least wants shifted, and the owner asked for an icon); a toast on every fall-back (a dozen screens opening in a row would say it a dozen times); a timer that re-says it after a quiet period (the repo wakes on no clock).
